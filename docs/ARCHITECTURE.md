# Архитектура

Расширение Chrome MV3 без сборки и серверной части, рассчитанное на одного пользователя и библиотеку в его профиле. Chrome владеет деревом закладок; расширение хранит связанные файлы и метаданные. Страницы в корне остаются стабильными точками входа. Перенос исходников в `src/` не меняет адреса интерфейса.

## Модули

| Область | Модули в `src/` | Ответственность |
| --- | --- | --- |
| Страницы | `popup.js`, `tab.js`, `settings.js` | Навигация, состояние окна и события интерфейса |
| Ресурсы | `resources-ui.js`, `resource-browser.js`, `collections-ui.js` | Вложения, сетка, просмотр и подборки |
| Полотно | `canvas-layout.js`, `resource-canvas.js` | Операции над деревом раскладки; отдельно DOM, drag/drop и сохранение |
| Библиотека | `resource-library.js`, `resource-directory.js` | SQL, синхронизация, файлы и дескриптор папки |
| Общая библиотека | `shared-library-client.js`, `shared-library-background.js`, `shared-library-server.js` | Доступ инкогнито к обычной библиотеке |
| Загрузки | `download-manager.js`, `download-offscreen.js`, `extension-bridge.js` | Постоянная очередь, сообщения и фоновые задачи |
| Медиа | `page-media.js`, `media-scan.js`, `media-picker.js`, `media-fetch.js`, `media-size.js`, `stream-download.js` | Поиск источников, разрешения, получение и сборка файлов |
| Превью | `bookmark-resources.js`, `bookmark-hover.js`, `page-preview.js`, `preview-queue.js`, `video-thumbnail.js` | Миниатюры, таймлапсы и подготовка |
| Общее | `model.js`, `file-size.js`, `toolbar-icon.js`, `popup-size.js`, `scrollbars.js`, `style.css` | Преобразования данных и оформление |

Модули импортируются напрямую. Сторонние сборки и лицензии находятся в `vendor/`.

## Выполнение

`tab.html` — окно action для текущей вкладки, `popup.html` — библиотека, `settings.html` — выбор пользовательской папки. Service worker `src/background.js` обновляет значки и обслуживает очередь.

Скрытый `download-offscreen.html` получает и собирает файлы, читает библиотеку и готовит превью после закрытия popup. `download-manager.js` сериализует изменения очереди Web Lock, сохраняет снимки в `chrome.storage.local` и запускает одну загрузку за раз. После перезапуска браузера незавершённая задача получает состояние `interrupted`; повтор использует сохранённый источник. Ревизии защищают от поздних сообщений со старым состоянием.

Сообщения проверяются по отправителю и типу операции. Путь worker обновлён в манифесте и проверках отправителя. Медиа требуют разрешённых origins. Функции для `scripting.executeScript` остаются автономными: их импорты в контекст страницы не переносятся.

## Каталог

`resource-directory.js` хранит дескриптор папки и её ID в IndexedDB. Смена корня открывает другую библиотеку. Начатая задача сохраняет привязку к исходной папке и проверяет её перед записью.

`resource-library.js` владеет `catalog.sqlite`, версией схемы и техническими путями. Версия схемы — 4; версии 1–3 обновляются при открытии. Метаданные отделены от файлов:

```text
<папка>/catalog.sqlite
<папка>/tree/f_<UUID>/f_<UUID>/b_<UUID>/r_<UUID>.<расширение>
```

| Таблицы | Данные |
| --- | --- |
| `meta` | Идентификаторы профиля и библиотеки |
| `nodes` | Chrome ID, UUID, родитель, название, URL, тип и присутствие узла |
| `resources`, `bookmark_tags` | Вложения и нормализованные теги |
| `collections`, `collection_resources` | Подборки и ссылки на ресурсы без копирования файлов |
| `resource_previews`, `resource_timelapses` | JPEG-обложки и таймлапсы |
| `pending_moves`, `cleanup`, `stale_folders` | Продолжение переносов и безопасная очистка |

Имена и URL не являются ключами. Удалённые закладки отмечаются отсутствующими, файлы сохраняются. Выборка папки использует рекурсивный SQL-запрос. Пользовательские значения передаются параметрами SQL. Встроенный просмотр ограничен растровыми изображениями и видео; HTML и SVG в нём не исполняются.

## Целостность

Операции каталога сериализуются Web Lock `bookmark-resource-library`; после получения блокировки база перечитывается. `createWritable()` публикует файл после успешного `close()`. Ошибка записи прерывает поток, исходный пользовательский файл не меняется.

Вложение сначала получает статус `pending`. После закрытия файла и проверки размера — `ready`. При повторном открытии завершённые файлы восстанавливаются, незавершённые записи остаются видимыми.

Перенос: резервирование назначения → копирование → побайтовая проверка → сохранение нового пути и очереди очистки → удаление проверенной старой копии. Несовпадающее назначение не перезаписывается. Неизвестные файлы и изменённые старые копии не удаляются; папки удаляются только пустыми. При прерванном восстановлении чтение может использовать оставшуюся копию ожидаемого размера.

Проверяются версия, целостность SQLite, внешние ключи, профиль и технические пути. Отсутствующий или пустой каталог при существующем `tree/` не заменяется новой базой. Чужой профиль и неизвестная версия отклоняются. Web Locks не защищают от внешнего SQLite-редактора.

`sql.js` загружает базу целиком и экспортирует её при записи. Переход на VFS или отдельный worker оправдан при подтверждённых задержках большого каталога. Уборка проекта не меняет схему и правила восстановления.

## Инкогнито и кеши

Манифест использует `incognito: split`. Клиент инкогнито передаёт запросы обычному worker через `chrome.storage.local`; тот вызывает offscreen обычного режима. Дескриптор папки и профиль библиотеки остаются в обычном контексте. Файлы передаются частями; временные передачи имеют таймаут и освобождение. Обложки и таймлапсы находятся в общей SQLite.

Ключи очереди загрузок различаются для обычного режима и инкогнито. Одна очередь не восстанавливает и не очищает задачи другой.

Миниатюры подготавливаются до трёх одновременно. Таймлапсы идут отдельной очередью и не задерживают обложки. Повторные запросы генерации одного ресурса объединяются. Закрытие просмотрщика останавливает видео и освобождает Blob URL; смена режима отключает наблюдателей и обработчики. Поколение рендера защищает интерфейс от запоздавших ответов.

## Состояние интерфейса

`popup.js` хранит навигацию и настройки в `localStorage`. Возврат фокуса не вызывает полной перерисовки. Шапка, сайдбар и лента сворачиваются вручную, состояние сохраняется.

Раскладка — дерево: строковый ID ресурса либо `{ axis, children, sizes? }`. `canvas-layout.js` отвечает за вставку, замену, обмен, удаление, размеры, восстановление и историю. Он не обращается к DOM или Chrome. `resource-canvas.js` связывает дерево с DOM и сохраняет раскладку в `chrome.storage.local`, с fallback для тестов.

Ключ включает ID библиотеки и область: все ресурсы, папку или подборку. Фильтр ленты не удаляет открытые ресурсы с полотна. Размеры сохраняются с деревом. История отмены действует в памяти окна, отдельно для каждой области.

## Проверки

Команды приведены в [README](../README.md#разработка). `check` проверяет синтаксис и локальные ссылки. Модульные тесты покрывают раскладку, каталог, восстановление и очередь. Браузерные сценарии проверяют действия пользователя, локальный FFmpeg, фоновые загрузки и реальное расширение в обычном режиме и инкогнито.

Тестовые каталоги и профили отделены от данных пользователя. Фикстуры подтверждают поддержанные сценарии, но не гарантируют совместимость со всеми внешними плеерами, DRM и кодеками.
